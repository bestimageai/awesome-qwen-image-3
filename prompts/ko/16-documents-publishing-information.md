# 문서, 출판, 정보 디자인

Qwen Image 3.0 프롬프트 10개입니다. 생성 전에 대괄호 안의 입력값을 바꾸세요. 따옴표 안의 문구는 정확히 재현하며, 명시적인 요청이 없으면 추가로 번역하지 않습니다. 결과물은 사람이 검토해야 합니다.

<a id="doc-01"></a>

## DOC-01 — 두 페이지 프로젝트 개요

```text
세로 프로젝트 개요 두 페이지를 나란히 둔 16:9 프레젠테이션을 만든다. [APPROVED COPY]로 첫 페이지에 목적과 배경, 둘째에 범위와 다음 단계를 넣는다. 여백과 제목 위계를 맞추고 페이지 번호는 제공된 경우에만 넣는다. 차콜 글자, 파란 선, 흰 종이를 사용한다. 더미 문구, 가상 날짜, 서명, 승인 도장은 넣지 않는다. 변수: 전체 문구와 페이지 대응표. 래스터 레이아웃 콘셉트이며 최종 문서에는 편집 가능한 조판이 필요하다.
```

<a id="doc-02"></a>

## DOC-02 — 제품 관리 리플릿

```text
[MANUFACTURER-APPROVED CARE INSTRUCTIONS]로 3:4 그림 관리 리플릿을 만든다. 제공된 행동 네 개를 2×2 격자로 놓고 각각 맞는 단순한 물체 일러스트와 정확한 라벨을 붙인다. 경고 문구는 별도의 아래 띠에 둔다. 세척 화학물질, 온도, 폐기 조언, 보증 조건을 지어내지 않는다. 대비 높은 글자와 절제된 파란 팔레트를 사용한다. 변수: 검증된 지침과 제품 참조. 게시 전에 모든 단계를 확인한다.
```

<a id="doc-03"></a>

## DOC-03 — 박물관 유물 라벨

```text
[VERIFIED OBJECT METADATA]로 4:3 박물관 라벨 콘셉트를 만든다. 왼쪽에 작고 허가된 유물 이미지, 오른쪽에 정확한 제목, 제작자, 날짜, 재료, 설명을 놓는다. 차분한 크림 배경과 읽기 쉬운 어두운 글자를 사용한다. 제공되지 않은 필드는 추정하지 말고 생략한다. 출처 이력, 평가액, 수장 번호, 기관 로고를 지어내지 않는다. 변수: 이미지와 승인된 메타데이터. 레이아웃 연구이며 진위나 소유권 증거가 아니다.
```

<a id="doc-04"></a>

## DOC-04 — 연차 보고서 펼침면

```text
[APPROVED REPORT COPY AND DATA]로 16:9 두 페이지 연차 보고서 레이아웃을 만든다. 왼쪽에는 제목 하나와 짧은 서술, 오른쪽에는 라벨이 분명한 차트 하나와 출처 주석을 넣는다. 일관된 편집 격자와 절제된 남색 강조를 사용한다. 모든 단위, 기간, 제한 조건을 유지한다. 재무 수치, 감사 문구, 서명, 보증을 지어내지 않는다. 변수: 검증된 문구, 데이터, 출처. 사실과 제작 검토가 필요한 디자인 콘셉트다.
```

<a id="doc-05"></a>

## DOC-05 — 회의 일정 카드

```text
[APPROVED SESSION TABLE]로 3:4 행사 일정을 만든다. 정확한 시작 시각, 세션 제목, 방을 세로 시간선에 넣고 동시 진행 세션은 시각적으로 묶는다. 위에는 행사명, 그 아래에는 제공된 시간대를 둔다. 아이보리에 큰 어두운 글자와 파란 구분선을 사용한다. 발표자, 휴식, 접근성 마련, 장소 세부를 지어내지 않는다. 변수: 일정과 정확한 문구. 시간 순서와 방 대응을 검증한다.
```

<a id="doc-06"></a>

## DOC-06 — 검토된 알림 카드

```text
[CLINICIAN-APPROVED TEXT]만 사용해 3:4 큰 글자 알림 카드를 만든다. 제공된 정보를 명확히 나뉜 행으로 정리하고 고대비 검은 글자와 파란 제목 하나를 사용한다. 이름, 양, 단위, 시간, 경고를 정확히 유지하고 용량, 진단, 의학 조언은 추가하지 않는다. 알약, 로고, 서명, 공식 인장을 생성하지 않는다. 변수: 승인된 문구와 제목. 시각 서식 콘셉트이며 실제 사용 전 자격 있는 전문가가 검증해야 한다.
```

<a id="doc-07"></a>

## DOC-07 — 도서관 회원 안내

```text
[APPROVED MEMBERSHIP RULES]로 가상의 지역 도서관 3:4 안내 리플릿을 만든다. “가입”, “대출”, “반납” 세 구역마다 단순한 일러스트 하나와 제공된 짧은 문구를 둔다. 크림 종이, 남색 글자, 넉넉한 간격을 사용한다. 요금, 신원 확인 요구, 운영시간, 대출 한도를 지어내지 않는다. 변수: 검증된 규칙과 승인된 제목. 개인 정보와 스캔 가능한 코드는 디자인에서 제외한다.
```

<a id="doc-08"></a>

## DOC-08 — 문서 비교 레이아웃

```text
제공된 짧은 공개 문서 두 버전을 비교하는 16:9 나란한 레이아웃을 만든다. 페이지 크기 비율을 동일하게 하고 [APPROVED CHANGED PASSAGES]만 옅은 노랑으로 강조한다. 패널은 “이전”, “수정”으로 표기한다. 모든 문구를 그대로 유지하며 법적 의미를 추론하거나 논평을 넣거나 바뀌지 않은 표현을 수정하지 않는다. 변수: 두 원문과 명시적 변경 대응표. 시각 비교 콘셉트이며 법률 검토나 변경 추적 파일이 아니다.
```

<a id="doc-09"></a>

## DOC-09 — 자원봉사 인계 시트

```text
[APPROVED TASK LIST]로 3:4 인계 시트 콘셉트를 만든다. “완료”, “진행 중”, “다음 근무” 구역으로 나누고 제공된 각 항목 옆에 체크박스 하나를 둔다. 상태가 명시되지 않으면 체크박스는 비워 둔다. 크고 읽기 쉬운 글자, 단순한 격자를 사용하고 장식 사진은 넣지 않는다. 이름, 마감일, 연락처, 완료 주장을 지어내지 않는다. 변수: 작업 목록과 제공된 상태. 최종 실무 사용에는 편집 가능한 텍스트가 필요하다.
```

<a id="doc-10"></a>

## DOC-10 — 전시 가격표

```text
[APPROVED ITEM TABLE]로 3:4 가상 전시 가격표 레이아웃을 만든다. 품목명, 크기, 가격을 명확한 세 열에 맞추고 품목마다 한 행을 둔다. 절제된 세리프 제목, 산세리프 숫자, 흰 배경을 사용한다. 통화 기호, 소수 구분자, 단위를 정확히 유지한다. 할인, 세금 처리, 판매 완료 상태, 작가 약력을 지어내지 않는다. 변수: 검증된 표와 제목. 조판 콘셉트이며 제안이나 거래 기록이 아니다.
```
