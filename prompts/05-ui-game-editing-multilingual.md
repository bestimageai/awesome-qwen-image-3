# Interfaces, controlled edits, and localization

Ten Qwen Image 3.0 prompt recipes. Replace bracketed inputs before generation. All quoted text is exact; no translation is implied unless explicitly requested. Outputs require human review.

## DIG-01 — Tool library mobile interface

```text
Create a 16:9 board showing three mobile screens for fictional app "Borrow Bench": catalog, item detail and reservation confirmation. Use ivory backgrounds, navy type, teal action buttons and consistent rounded cards. Show a yellow drill as the selected item. Render only "Borrow Bench", "Find a tool", "Cordless drill", "Reserve", "Collection time", "Saturday 10:00", "Reservation saved", and "View booking" in their appropriate screens. No prices, personal information or extra navigation labels. This is a static interface concept; do not imply functioning controls.
```

## DIG-02 — CSV import review screen

```text
Create a 16:9 desktop interface mockup for fictional inventory app "Stockroom". Show an import review table with columns "Item", "Quantity", and "Status"; include three supplied sample rows, one visibly marked "Needs review". Above the table render "Review your import"; below it place "Back" and "Import valid rows" buttons. Use a clean white layout with amber error emphasis and a readable sidebar containing only "Inventory". Preserve supplied data and do not display personal information. Variables: sample rows and approved copy.
```

## DIG-03 — Regional rail homepage

```text
Create a 16:9 desktop homepage concept for fictional travel planner "Local Lines". Use a large coastal-train photograph on the right and a practical search panel on the left. Render exactly "Take the slower route", "From", "To", "Travel date", and "Find journeys"; keep fields empty. Use cream background, dark-green controls and generous spacing. Add no real schedules, fares, operator logos or availability claims. Keep the train physically plausible and interface text separate from the photograph. Variables: region imagery and approved headline.
```

## DIG-04 — Cooperative game HUD

```text
Create a 16:9 static HUD concept for a fictional mountain-delivery game. Keep the central sixty percent of a snowy trail unobstructed. Place a compact compass at the top, two teammate status bars at the upper left and three inventory slots at the lower right. Render only "North", "Team", "Parcel", "Rope", and "Map". Use high-contrast shapes with restrained amber highlights, not cinematic floating holograms. Avoid real military insignia, unreadable microtext and excessive overlays. Variables: game setting and approved labels.
```

```text
Use Image 1 as the edit target and [APPROVED SOURCE-TO-TARGET TEXT MAP] as the only replacement copy. Preserve type weight and hierarchy; adjust line breaks only where the target language requires it. Keep punctuation, accents and reading direction correct. ```
```

## DIG-06 — Photo damage repair

```text
Use one authorized scanned photograph as the edit target. Repair only visible dust, scratches and fold damage, reconstructing small missing areas from neighboring texture. Preserve identity, age, expression, crop, clothing, original grain and tonal range. Do not colorize a monochrome source, smooth skin, open eyes or invent background objects. Keep uncertain large missing regions unchanged rather than hallucinating details. Output one restored image without comparison labels or watermark. Variables: source photograph and explicitly marked repair areas.
```

## DIG-07 — Three-reference product composite

```text
Use Image 1 as the base tabletop scene, Image 2 as the exact ceramic cup reference and Image 3 only as the glaze-color reference. Place one cup from Image 2 on the empty coaster in Image 1 and apply only the supplied glaze hue. Preserve the base camera, crop, surrounding objects and cup geometry. Match light direction, contact shadow, perspective and reflections. Do not copy objects or text from Image 3. Add no text. Variables: three authorized images and intended cup placement.
```

## DIG-08 — Sketch to reading room

```text
Use an approved room sketch as the layout reference. Create a 4:3 realistic reading-room concept with pale oak shelves, a moss-green bench and diffuse ceiling light. Preserve every wall, window, doorway and furniture footprint from the sketch; use the material palette only to finish existing surfaces. Keep perspective coherent and aisle widths visually unchanged. Add no people, extra furniture, plants or signs. This is an illustrative concept, not a measured construction drawing. Variables: sketch and approved materials.
```

## DIG-09 — Accessible empty state

```text
Create a 3:4 mobile interface mockup for an empty saved-reading list. Use a cream background, navy text and one small illustration of three closed books. Render exactly "Nothing saved yet", "Keep useful reads in one place", and "Explore articles". Place the explanation beneath the heading and a large button below; leave comfortable margins. Use high contrast and no tiny text, loading skeleton, fake article cards or notification badges. This is a static design proposal; accessibility still requires implementation testing.
```

## DIG-10 — Language direction comparison

```text
Create a 16:9 side-by-side interface typography board from [APPROVED ENGLISH AND ARABIC COPY]. The left panel uses left-to-right alignment; the right uses natural right-to-left alignment. Preserve the same component hierarchy, spacing and two button roles while adapting reading order. Keep product photographs unchanged rather than mirroring them. Render only supplied strings, with connected Arabic glyphs and intact Latin brand names. No transliteration, duplicate source text or invented copy. Variables: paired strings and component labels; require fluent Arabic review.
```
